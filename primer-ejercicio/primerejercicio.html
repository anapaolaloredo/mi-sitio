Ejercicio Guiado: Cloud Models Classifier

Aplicación de escritorio en Java que clasifica descripciones de servicios Cloud en IaaS, PaaS, SaaS o FaaS, desarrollada con apoyo de IA generativa siguiendo el ejercicio guiado.

Parte 1. Desarrollo inicial en Java

Se creó el proyecto cloud_models_classifier en Visual Studio Code, con la estructura estándar src/com/cloudclassifier/. Se utilizó IA generativa con el prompt indicado en la guía para generar el primer prototipo: una aplicación Swing con captura de nombre/apellido, campo de texto libre y clasificación por reglas/Regex.

Prompt utilizado: "Crea una aplicación de escritorio en Java con interfaz gráfica (GUI)... analiza el texto y determina si corresponde a IaaS, PaaS, SaaS o FaaS usando reglas sencillas, palabras clave y Regex..."

Parte 3. Mejorar la arquitectura de la aplicación

Se refactorizó el código generado por la IA incorporando:

Separación

GUI (MainFrame.java) separada por completo de la lógica (ClassifierService.java). La GUI no contiene reglas de clasificación.

Métodos independientes

Un método por categoría: analizarIaaS, analizarPaaS, analizarSaaS, analizarFaaS.

Validación

Se valida que nombre, apellido y descripción no estén vacíos antes de clasificar, mostrando diálogos de advertencia en la GUI.

Manejo de errores

Excepciones controladas al clasificar; en la versión CLI se capturan y se reportan por stderr con código de salida distinto de cero.

Parte 5. Evolucionar de Regex hacia NLP

Se incorporó procesamiento básico de lenguaje natural (NLP) al ClassifierService, siguiendo el flujo: texto del usuario → preprocesamiento → tokenización/normalización → extracción de características → reglas/scoring → categoría.

  • Conversión a minúsculas y limpieza de texto (eliminación de puntuación/símbolos).
  • Tokenización: separación del texto en palabras individuales.
  • Eliminación de stopwords: se descartan palabras sin valor semántico ("el", "la", "de", "para", etc.) usando un conjunto (Set<String>) de stopwords en español.
  • Normalización: eliminación de tildes con java.text.Normalizer, para que "función" y "funcion" se traten como equivalentes.
  • Identificación de palabras/frases clave: coincidencia por secuencia de tokens (no por subcadena), soportando frases de varias palabras como "máquina virtual" y evitando falsos positivos como "funcional" activando FaaS.
  • Asignación de puntuaciones (scores): cada categoría acumula un puntaje según sus coincidencias; gana la de mayor puntaje.

No se utilizó un LLM para responder la categoría: el objetivo de esta parte fue comprender cómo el preprocesamiento de lenguaje natural mejora un clasificador basado en reglas, manteniendo el enfoque de reglas + scoring.

Parte 6. Interfaz de línea de comandos

Se creó CloudClassifierCli.java, que reutiliza la misma lógica que la GUI a través de ClassifierService.clasificar(). La arquitectura final: GUI y CLI son ambas interfaces de usuario que llaman al mismo componente central de clasificación (NLP + reglas/scoring), el cual produce el resultado (IaaS/PaaS/SaaS/FaaS).

Errores encontrados

  • El código generado inicialmente por la IA colocaba toda la lógica de clasificación dentro de la clase de la GUI; se separó en ClassifierService siguiendo la arquitectura pedida en la Parte 3.
  • El matching por subcadena del prototipo inicial generaba falsos positivos (ej. "funcional" activaba FaaS); se corrigió comparando por tokens completos en la Parte 5.
  • Frases clave de más de una palabra (ej. "máquina virtual") no se detectaban correctamente con Regex simple; se resolvió con búsqueda de subsecuencia de tokens.

Conclusiones

El ejercicio permitió comprobar cómo un clasificador basado únicamente en reglas y Regex puede mejorarse de forma significativa incorporando un pipeline de NLP básico, sin necesidad de un modelo de lenguaje. Además, mantener la lógica de clasificación separada de la interfaz (GUI y CLI) permitió reutilizar el mismo componente en ambas interfaces sin duplicar código, cumpliendo con los principios de arquitectura solicitados en la guía.
